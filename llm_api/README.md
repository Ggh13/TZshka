## Эндпоинты для взаимодействия с LLM_API

### 1. **Загрузка ТЗ в виде сплошного текста**

**POST** `llm/text`

**Request:**
```json
{
  "content": "some_text"
}
```
- `content` - текст технического задания.

**Response (200)**

```json
{
  "success": true,
  "code": 200,
  "data": {
    "status": "valid",
    "issues": [
        {
            "rule_id": "...",
            "problem": "...",
            "explanation": "..."
        },
    ],
    "feedback": "..."
  } | null,
  "error": {
            "type": "...",
            "message": "..."
  } | null
}
```
- **success** — `boolean`  
  Флаг успешности запроса.  
  - `true` — запрос обработан успешно  
  - `false` — произошла ошибка.

- **code** — `integer`  
  HTTP-код ответа сервера.

- **data** — `object | null`  
  Полезные данные ответа. Присутствует только при `success = true`.

  **Поля объекта `data`:**

  - **status** — `string`  
    Результат проверки технического задания.  
    Возможные значения:  
    - `valid` — нарушений не найдено  
    - `issues_found` — обнаружены проблемы.

  - **issues** — `array<object>`  
    Список найденных проблем. Пустой массив, если нарушений нет.

    **Поля элемента массива:**

    - **rule_id** — `string`  
      Идентификатор правила, которое было нарушено.

    - **problem** — `string`  
      Название обнаруженной проблемы.

    - **explanation** — `string`  
      Подробное объяснение причины проблемы.

  - **feedback** — `string`  
    Общая объективная оценка технического задания, сгенерированная LLM.

- **error** — `object | null`
    
  Информация об ошибке. Для успешного ответа всегда `null`.
  
  **Поля объекта `error`:**
  - **type** - тип ошибки
  - **message** - описание ошибки

### 2. **Загрузка ТЗ в виде файла .txt**

**POST** `llm/text_file`

**Request (multipart/form-data):**

```
file: tz.txt
```
- `file` - текст технического задания в файле формата .txt.

**Response (200)**

```json
{
  "success": true,
  "code": 200,
  "data": {
    "status": "valid",
```
